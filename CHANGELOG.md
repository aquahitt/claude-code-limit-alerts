# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [Unreleased]

### Added

- Экспериментальный mod `mods/limit-alerts-status/` — отдельный плагин на
  TypeScript-хуках Claude Code. Показывает лимиты в строке статуса плагина
  (`$.ui.status`), не трогая `statusLine` в `~/.claude/settings.json`. Берёт
  свежий `usage-monitor-cache.json`, а без него — проценты 5ч/7д, которые
  Claude Code сам получает из ответов API. В плагин `limit-alerts` и в
  marketplace не входит: API модов пока в early access. Запуск:
  `claude --plugin-dir mods/limit-alerts-status`.

### Fixed

- Ответ HTTP 429 (слишком много запросов) от endpoint лимитов писался в лог
  как «токен, вероятно, истёк», что уводило диагностику не туда. Теперь лог
  различает 401/403 (токен), 429 (ограничение частоты, пройдёт само) и прочие
  коды.
- `uninstall.sh` удаляет оставшуюся блокировку `usage-monitor.lock`, если
  проверку прервали посреди обновления состояния.

## [0.6.0] - 2026-10-09

### Added

- Установка как плагин Claude Code — теперь основной способ.
  `/plugin marketplace add aquahitt/claude-code-limit-alerts`, затем
  `/plugin install limit-alerts@claude-code-limit-alerts`. Хуки регистрируются
  самим плагином, `~/.claude/settings.json` при этом не правится вообще.
- Настройки плагина через `userConfig`: язык, пороги предупреждения и
  критического уровня, выключатели уведомлений «требуется внимание», подсказки
  о `/compact`, statusline и фонового агента. Statusline и агент выключены по
  умолчанию — они пишут за пределы плагина, поэтому включаются явно.
  Скрипты читают `CLAUDE_PLUGIN_OPTION_*` только когда запущены из самого
  плагина: эти имена общие для всех плагинов и протекают в чужие хуки, так что
  классическая установка их игнорирует.
- Скиллы `limit-alerts:status`, `limit-alerts:setup` и
  `limit-alerts:uninstall`. Последний нужен потому, что отключение плагина не
  отменяет запись statusline и регистрацию launchd-агента.
- `scripts/plugin-bootstrap.sh` — хук `SessionStart`: зеркалит два скрипта,
  которым нужен стабильный путь, в `${CLAUDE_PLUGIN_DATA}/bin`, применяет
  включённые statusline и launchd и один раз предупреждает, если рядом
  работает классическая установка.

### Changed

- Каталог состояния резолвится через `UM_STATE_DIR` с откатом на
  `~/.claude/scripts`. Классическая установка попадает ровно туда же, куда и
  раньше. `CLAUDE_PLUGIN_DATA` в цепочке намеренно нет: эту переменную
  экспортирует тот плагин, чей хук выполняется, и она протекает в посторонние
  шеллы — классическая установка в сессии с любым включённым плагином иначе
  молча унесла бы своё состояние в чужой каталог.
- `generate_plist` принимает необязательные label, путь к скрипту и файл
  ошибок. `install.sh` и `update.sh` вызывают её без изменений — проверено
  побайтовым сравнением сгенерированного plist до и после. Агент плагина живёт
  под отдельным label `com.claude.usage-monitor.plugin`, поэтому две установки
  никогда не спорят за один plist.

### Fixed

- Одно и то же предупреждение о лимите могло прийти дважды, если Stop-хук,
  `SessionStart` и launchd-агент запускались одновременно: оба запуска читали
  одно состояние и оба считали порог новым. Теперь обновление состояния идёт
  под блокировкой (`usage-monitor.lock` в каталоге состояния); запуск, который
  не дождался её за 5 секунд, просто выходит — держатель блокировки сообщает то
  же самое. Блокировка старше минуты считается брошенной и снимается.

## [0.5.0] - 2026-08-25

### Removed

- Авто-продолжение сессии после сброса лимита целиком: скрипт
  `auto-resume.sh` и его состояние `auto-resume-state.json`, уведомление 🚫 с
  командой продолжения, автозапуск воркера в новом окне терминала, флаги
  `install.sh` `--no-auto-resume` и `--auto-resume-autostart`, переменные
  `UM_BLOCK_PCT`, `UM_SESSION_TTL`, `UM_RESUME_PROMPT`, `UM_RESUME_MAX_WAIT`.

  Причина: Claude Code 2.1+ делает это сам — тумблер «Continue automatically
  at usage limit» в `/config` (`autoContinueAtUsageLimit` в
  `~/.claude/settings.json`). Встроенное продолжение не требует ни выхода из
  сессии, ни второго терминала, ни `--resume`, а внешний воркер требовал всего
  этого — и, работая рядом со встроенным, продолжал бы один разговор дважды,
  двумя процессами на один `session_id`.

  `install.sh` и `update.sh` при обновлении удаляют оставшиеся от прежних
  версий `auto-resume.sh`, файл состояния и lock-файлы. Мониторинг лимитов,
  пороги 🟡/🔴, уведомление о сбросе окна, statusline и подсказка о `/compact`
  не изменились; `usage-monitor.sh limits` сохранён.

## [0.4.0] - 2026-08-21

### Added

- `auto-resume.sh`: дожидается сброса исчерпанного лимита и продолжает
  прерванную сессию интерактивно (`claude --resume`), перепроверяя реальные
  лимиты после `resets_at`, а не доверяя одному только времени — недельный
  лимит регулярно переживает пятичасовое окно.
- `usage-monitor.sh` теперь записывает активную сессию из stdin хука
  (`session_id`, `cwd`, `transcript_path`) в `auto-resume-state.json` и
  уведомляет один раз за окно, когда лимит сессии исчерпан, копируя команду
  продолжения в буфер обмена.
- `usage-monitor.sh limits`: машиночитаемый снимок лимитов
  (`kind|percent|resets_at|scope`), без заголовка и локализации; учитывает
  `UM_CACHE_TTL=0` для живого запроса без кэша.
- `compact-advisor.sh`: хук `Stop`, подсказывающий удачный момент для
  `/compact` — контекст выше `UM_COMPACT_WARN` (по умолчанию 70%), ход
  закончился без `tool_use`, и нет незакрытых задач. Хук не может выполнить
  `/compact` сам — это осознанно только сигнал.
- Флаги `install.sh`: `--no-auto-resume`, `--auto-resume-autostart`,
  `--no-compact-advisor`, `--auto-compact-window <токены>` (100000–1000000,
  записывается в `~/.claude/settings.json`).
- `~/.claude/scripts/.limit-alerts-options` запоминает выбор, сделанный при
  установке, чтобы `update.sh` никогда не включал фичу, от которой
  пользователь отказался.
- Statusline: модель сессии, уровень `effort` и заполненность контекста —
  берутся из собственного stdin statusline (без лишнего I/O), плюс модель
  работающего субагента, когда она отличается от модели сессии — читается из
  `<проект>/<session_id>/subagents/` и считается «живой» по времени
  изменения транскрипта (`UM_SUBAGENT_TTL`, по умолчанию 180 с). Несколько
  субагентов на одной модели схлопываются в `⇢ 2× Haiku 4.5`. Рядом
  показывается модель встроенного советника (`/advisor`, ключ `advisorModel`),
  когда её семейство отличается от модели сессии — `adv Fable`; отключается
  через `UM_STATUSLINE_ADVISOR=0`. Модели сравниваются целиком, когда обе
  стороны несут версию (Sonnet 4 и Sonnet 4.5 остаются разными), и по семейству
  — только когда одна из сторон голый алиас без версии. Это же убирает ложное
  `⇢` для субагента, чья модель известна лишь по алиасу из `meta.json`.
- Флаги `install.sh` `--no-statusline-model` и `--no-subagent-model` —
  каждый запоминается в `.limit-alerts-options` и вшивается в установленный
  скрипт так же, как `--lang` раньше.

### Changed

- Statusline: недельный лимит с привязкой к модели теперь с префиксом
  (`нед.` / `wk`), чтобы `Fable 4%` нельзя было принять за модель, которая
  работает прямо сейчас, теперь когда рядом на строке может стоять настоящее
  имя модели.
- `uninstall.sh` удаляет новые скрипты, файлы состояния и lock-файлы, а
  `autoCompactWindow` убирает только если его выставил этот же проект.

### Fixed

- `update.sh` больше не теряет язык, выбранный при установке: он копирует
  скрипты из репозитория поверх установленных, а выбор `--lang` вшит именно
  в установленные копии, так что после любого обновления уведомления молча
  возвращались к русскому. Теперь выбор восстанавливается из
  `.limit-alerts-options`.
- Флаги со значением (`--lang`, `--proxy`, `--auto-compact-window`) больше не
  завершаются молча с кодом 1, если значение не указано — печатается
  внятное сообщение.

## [0.3.1] - 2026-07-23

### Fixed
- `refresh_via_cli()` в `usage-monitor.sh` теперь сверяет `cachedUsageUtilization.fetchedAtMs` до и после вызова `claude -p /usage`, а не доверяет одному коду возврата — при недоступности API (например, Team-подписка, заблокированная за неоплату) CLI мог завершаться успешно, но не обновлять кэш, из-за чего `usage-monitor.log` неделями писал ложное «refreshed local usage cache», маскируя реальную причину задержки в обнаружении сброса лимита.

## [0.3.0] - 2026-07-18

### Added
- `install.sh`/`update.sh` теперь поддерживают флаг `--proxy <url>` для фонового launchd-агента: без флага прокси-настройки (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`, без учёта регистра) подхватываются автоматически из текущего шелла. Решает ситуацию, когда фоновый агент за корпоративным прокси/VPN не мог получить данные о лимитах — притом что `claude -p "/usage"` в обычном терминале работал нормально.
- `--proxy ""` отключает проброс прокси для агента.

## [0.2.2] - 2026-07-17

### Added
- `usage-monitor.log` теперь автоматически обрезается: как только файл превышает 1МБ, остаются последние 2000 строк, чтобы лог не рос бесконечно на фоновом cron.

## [0.2.1] - 2026-07-17

### Fixed
- `claude -p "/usage"` в `refresh_via_cli()` теперь резолвится явными кандидатами (`~/.local/bin/claude`, Homebrew, `/usr/local/bin`), а не только через `PATH` — launchd запускает `cron`-джобу с голым `PATH` (`/usr/bin:/bin:/usr/sbin:/sbin`, без профиля пользователя), из-за чего фикс 0.2.0 для team/протухших токенов в реальном фоне не срабатывал (`command -v claude` ничего не находил).

## [0.2.0] - 2026-07-17

### Added
- Версионность проекта (`VERSION`, этот `CHANGELOG.md`).
- `update.sh` — синхронизирует установленные скрипты, launchd-агент и хуки с текущим состоянием локальной копии репозитория, без `git pull` внутри себя. Поддерживает `--dry-run`.
- `usage-monitor.sh status` теперь первой строкой печатает установленную версию.

### Changed
- Логика регистрации хуков (`add_hook` и обёртки над ней) вынесена в `lib/hooks.sh`, используется и `install.sh`, и `update.sh` — раньше была продублирована.

## [0.1.0] - 2026-07-16

### Added
- Мониторинг лимитов Claude Code (сессия 5ч, неделя): уведомления и сообщения в интерфейсе Claude Code при приближении к порогам 80%/95% и при сбросе окна.
- Уведомления «требуется внимание» (баннер + звук) на события Notification/Stop.
- Statusline-обёртка с процентами всех лимитов.
- Фоновый launchd-агент (проверка каждые 5 минут), `install.sh`/`uninstall.sh`.

### Fixed
- Ложные алерты о сбросе окна из-за ±1с джиттера `resets_at` в ответе API.
- Тихие сбои опроса (`fetch_usage`) теперь пишутся в `usage-monitor.log` с указанием причины, вместо молчаливого `exit 0`.
- Для team/org-аккаунтов (403 на живом эндпойнте) и протухших OAuth-токенов — принудительное обновление локального кэша через `claude -p "/usage"` в режимах `cron`/`status`.
