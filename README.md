# claude-code-limit-alerts

**Русский** | [English](README.en.md)

Уведомления для Claude Code: мониторинг лимитов подписки (приближение к исчерпанию,
сброс окна, проценты в statusline) и «требуется внимание» — баннер со звуком, когда
Claude ждёт разрешения, ответа или закончил задачу.

> 🍎 **Пока только macOS.** Поддержка Windows и Linux запланирована — см. [Roadmap](#roadmap).

## Что вы получаете

**macOS-уведомления и сообщения в интерфейсе Claude Code:**

```
🟡 Лимит «Сессия (5ч)»: 82%, сброс в 18:00
🔴 Лимит «Неделя (все модели)»: 96% — почти исчерпан, сброс в сб 10:00
♻️ Лимит «Сессия (5ч)» сброшен (было 96%, сейчас 3%)
⏳ Лимит «Неделя (все модели)»: 46% — при таком темпе кончится ~чт 14:00, сброс сб 10:00
💳 Расходуются платные usage credits: $4.20
```

**Прогноз** ⏳ отвечает на вопрос «хватит ли до сброса?» раньше, чем сработает
порог 80%: если при нынешнем темпе лимит кончится до сброса окна, приходит одно
уведомление на окно. Темп считается по истории замеров: для 5-часового окна —
по последнему часу, для недели — по последним суткам (с ночами и перерывами).
Прогноз молчит, пока данных мало, ниже 25% недели и когда запас до сброса
невелик — ложная тревога хуже, чем никакой. **Платные credits** 💳: когда лимиты
подписки кончились и начали тратиться деньги, и на 80%/95% лимита расходов.

**Statusline с процентами всех лимитов** (зелёный / жёлтый ≥ 80% / красный ≥ 95%):

```
[ваш statusline] | 5ч 71% · 7д 46% ▲8 · нед. Fable 4%
```

`▲8` (жёлтый) — неделя на 8 пунктов впереди равномерного темпа: прошло 38%
недели, а потрачено 46%, при таком темпе лимит кончится до сброса. `▼18`
(голубой) — наоборот, на 18 пунктов позади: часть лимита сбросится
неиспользованной, а подписка оплачена в любом случае. Стрелка появляется при
отклонении от 5 пунктов, не раньше чем через 12 часов после начала окна.

**Уведомления «требуется внимание»** — когда Claude ждёт разрешения/ответа или
закончил работу, приходит баннер со звуком. В заголовке — имя сессии (или папка
проекта) и git-ветка, в подзаголовке — последний ваш запрос, чтобы сразу понять,
в какой терминал переключиться:

```
Claude: stroi-homes (develop)          ← какая сессия
исправь баг с уведомлениями…           ← над чем работает
Нужно разрешение или ответ             ← что случилось   (звук: Funk)
Задача завершена                       ←                  (звук: Glass)
```

Звук проигрывается напрямую через `afplay` — работает, даже если баннеры
не разрешены в Центре уведомлений.

**Ручная проверка в терминале:**

```
$ ~/.claude/scripts/usage-monitor.sh status
claude-code-limit-alerts vX.Y.Z
Сессия (5ч)           71%  сброс: 16.07 18:00  · кончится ~17:10
Неделя (все модели)   46%  сброс: 17.07 10:00  · по графику 38%
Неделя (Fable)         4%  сброс: 17.07 10:00  · по графику 38%  · к сбросу ~10% (останется 90%)
Расход недели по продуктам: Claude Code 88%, чаты 12%
```

«По графику» — где была бы неделя при равномерном расходе. «Кончится» —
прогноз, если лимит при нынешнем темпе исчерпается до сброса. «К сбросу ~10%
(останется 90%)» — обратный случай: при нынешнем темпе к сбросу будет
потрачено около 10%, остальное пропадёт. Строка о продуктах — доли того, что
потрачено за неделю (Claude Code, чаты, Cowork), а не доли лимита; она
появляется, когда продуктов с расходом два и больше. Если тратились платные
credits, ниже будет и их сумма.

Если свежие данные получить не удалось (например, endpoint ответил 429),
`status` показывает последний кэш с пометкой «⚠ Свежих данных нет — показан
кэш от … (N мин назад)», а окна, которые с тех пор уже сбросились, помечает
«(уже сброшен)». В плагине то же самое делает скилл `limit-alerts:status`.

## Как это работает

- Скрипт опрашивает тот же endpoint, что и команда `/usage` в Claude Code
  (`api.anthropic.com/api/oauth/usage`), OAuth-токен берётся из macOS Keychain —
  никаких дополнительных ключей и логинов не нужно.
- **Хуки Claude Code** (`Stop` + `SessionStart`) показывают предупреждения прямо
  в интерфейсе после хода и при старте сессии.
- **launchd-агент** проверяет лимиты каждые 92 секунды в фоне — уведомление о сбросе
  окна придёт, даже если Claude Code закрыт.
- **Два режима запуска.** Плагин регистрирует хуки сам и хранит состояние в
  своём каталоге данных; `install.sh` кладёт скрипты в `~/.claude/scripts` и
  дописывает хуки в `~/.claude/settings.json`. Логика мониторинга в обоих
  случаях одна и та же — это одни и те же файлы.
- **Statusline-обёртка** дописывает проценты к вашему существующему statusline
  (он сохраняется и продолжает работать). Для каждого окна берётся более
  свежая из двух цифр: та, что Claude Code передаёт в statusline из последнего
  ответа API этой сессии, или та, что монитор получил для всего аккаунта, —
  поэтому строка учитывает и работу в других терминалах, на других
  устройствах, на claude.ai, даже пока этот терминал просто открыт. Устаревший
  кэш statusline обновляет сама, в фоне, не задерживая отрисовку. Несколько
  открытых терминалов — простаивающих или работающих — показывают одну и ту
  же, самую свежую цифру и делают один запрос на всех. Когда окно
  доходит до порога предупреждения,
  рядом появляется время его сброса: `5ч 84% ↻00:20`.
- Уведомления не спамят: по одному на порог (80% и 95%) в рамках одного окна,
  сброс отмечается только если использование было ≥ 50%.

Подробности — в [docs/how-it-works.md](docs/how-it-works.md).

## Подсказка о сжатии и модель в statusline

**Продолжение после сброса лимита делает сам Claude Code.** В `/config` есть
тумблер «Continue automatically at usage limit» (ключ
`autoContinueAtUsageLimit` в `~/.claude/settings.json`): сессия сама дожидается
сброса и продолжает работу — без выхода, без второго терминала и без
`--resume`. В версиях ≤ 0.4.0 этот проект делал то же самое снаружи, скриптом
`auto-resume.sh`; начиная с 0.5.0 он удалён, потому что внешний воркер не может
сделать это лучше, а работая одновременно со встроенным продолжением — продолжал
бы один разговор дважды. `install.sh` и `update.sh` убирают оставшиеся от
прежних версий файлы.

**Подсказка о `/compact`.** Хук не может выполнить `/compact` — в схеме вывода
хуков такой команды нет. Поэтому `compact-advisor.sh` присылает сигнал в
момент, когда сжатие обойдётся дешевле всего: контекст перевалил за порог
(по умолчанию 70%), ход закончился ответом (а не вызовом инструмента) и нет
незакрытых задач.

Полностью автоматическая страховка — сдвинуть встроенный порог Claude Code:

```bash
./install.sh --auto-compact-window 140000   # 100000..1000000 токенов
```

**Модель в statusline.** Строка состояния показывает модель сессии, уровень
`effort` и заполненность контекста, а когда работает субагент на другой
модели — и его модель:

```
myproject (main) | Opus 5/high · adv Fable · ctx 72% · ⇢ Haiku 4.5 | 5ч 66% · 7д 7% · нед. Fable 4%
```

Всё это приходит в statusline на stdin, так что сегмент не стоит ни одного
обращения к сети или диску. Исключение — модель субагента: она берётся из
`~/.claude/projects/<проект>/<session_id>/subagents/`, и «работает сейчас»
определяется по времени последней записи (`UM_SUBAGENT_TTL`, по умолчанию
180 с). Субагент, молчащий дольше этого (один долгий вызов инструмента),
временно пропадает из строки. Субагенты на модели сессии не показываются,
несколько на одной модели схлопываются в `⇢ 2× Haiku 4.5`.

`adv Fable` — модель встроенного советника Claude Code (команда `/advisor`,
ключ `advisorModel` в `settings.json`). Показывается только когда её семейство
отличается от модели сессии, поэтому `advisorModel: opus` при сессии на Opus
ничего не добавляет. Вызовы советника — отдельные запросы со своим контекстом,
они не заполняют окно сессии и на `ctx` не влияют.

`нед. Fable 4%` — это **недельный лимит с привязкой к модели**, а не
работающая модель; префикс появился как раз потому, что рядом теперь стоит
настоящее имя модели. Не путайте с `adv Fable`: первое — сколько осталось от
недельной квоты этой модели, второе — чем вы советуетесь.

Отключить любую из фич: `./install.sh --no-compact-advisor`, `./install.sh --no-statusline-model`,
`./install.sh --no-subagent-model`.

## Установка

Требования: macOS, [jq](https://jqlang.github.io/jq/) (`brew install jq`),
Claude Code с авторизацией по подписке (Pro/Max).

Два способа. Плагин — основной; `install.sh` остаётся для тех, кому нужен
`--auto-compact-window` или установка без маркетплейса.

### Плагином (рекомендуется)

```
/plugin marketplace add aquahitt/claude-code-limit-alerts
/plugin install limit-alerts@claude-code-limit-alerts
```

Хуки регистрирует сам Claude Code — `~/.claude/settings.json` при этом не
правится. Всё состояние живёт в каталоге данных плагина и переживает
обновления.

Настройки — `/plugin` → limit-alerts → Configure:

| Параметр | По умолчанию | Действие |
|---|---|---|
| `lang` | `ru` | язык уведомлений (`ru` / `en`) |
| `warn` | `80` | порог 🟡 в процентах |
| `crit` | `95` | порог 🔴 в процентах |
| `attention` | вкл. | уведомления «требуется внимание» |
| `compact_advisor` | вкл. | подсказка о `/compact` |
| `forecast` | вкл. | прогноз ⏳: лимит кончится до сброса |
| `spend_alert` | вкл. | уведомления 💳 о платных usage credits |
| `statusline_pace` | вкл. | `▲N` / `▼N` — темп недели в statusline |
| `statusline` | **выкл.** | проценты лимитов в statusline |
| `launchd` | **выкл.** | фоновый агент, проверка каждые 92 секунды |

Последние два выключены намеренно: они пишут за пределы плагина — в
`~/.claude/settings.json` и в `~/Library/LaunchAgents`. Включите их в диалоге
настройки, и изменения применятся при следующем старте сессии либо сразу по
`/limit-alerts:setup`. Существующая statusline не затирается: она сохраняется
и продолжает отрисовываться, проценты дописываются после неё.

Скиллы плагина:

| Скилл | Действие |
|---|---|
| `/limit-alerts:status` | показать текущие лимиты |
| `/limit-alerts:doctor` | проверить установку, если что-то не работает |
| `/limit-alerts:setup` | применить настройки statusline и агента сейчас |
| `/limit-alerts:uninstall` | убрать statusline и агента перед удалением плагина |

> ⚠️ Не держите плагин и `install.sh` одновременно: хуки сработают дважды и
> уведомления задвоятся. Плагин замечает это и один раз предупреждает.
> Statusline и агента он в таком случае не трогает вовсе.

### Скриптом `install.sh`

```bash
git clone https://github.com/aquahitt/claude-code-limit-alerts.git
cd claude-code-limit-alerts
./install.sh
```

Флаги установщика:

| Флаг | Действие |
|---|---|
| `--no-statusline` | не трогать statusline |
| `--no-launchd` | без фонового агента (только хуки) |
| `--no-attention` | без уведомлений «требуется внимание» |
| `--lang en` | уведомления на английском (по умолчанию — русский) |
| `--no-compact-advisor` | без подсказки о `/compact` |
| `--auto-compact-window <токены>` | сдвинуть встроенный порог авто-сжатия Claude Code (100000–1000000); влияет на все сессии |
| `--no-statusline-model` | statusline без модели/effort/контекста/субагента — только лимиты |
| `--no-subagent-model` | в statusline модель сессии есть, модель субагента — нет |
| `--no-forecast` | без прогноза ⏳ |
| `--no-spend-alert` | без уведомлений 💳 о платных credits |
| `--no-statusline-pace` | без `▲N` / `▼N` в statusline |

После установки перезапустите Claude Code (или откройте один раз `/hooks`),
чтобы подхватились новые хуки. Перед изменением `~/.claude/settings.json`
создаётся бэкап.

## Обновление

Плагин обновляется через `/plugin` — Claude Code сам подтягивает новую версию.
Зеркало скриптов в каталоге данных пересобирается автоматически при первом
старте сессии после обновления.

Классическая установка:

```bash
git pull
./update.sh
```

Сверяет установленную версию (`~/.claude/scripts/.limit-alerts-version`) с
`VERSION` в репозитории, перекладывает изменившиеся скрипты, перезагружает
launchd-агент при изменении конфигурации и дозаявляет хуки — без
переустановки того, что вы не ставили (`--no-statusline`/`--no-launchd`/
`--no-attention` по-прежнему уважаются). Флаг `--dry-run` показывает, что
будет сделано, ничего не меняя. Список изменений между версиями — в
[CHANGELOG.md](CHANGELOG.md).

## Настройка

Пороги и поведение настраиваются переменными окружения (или правкой дефолтов
в начале `usage-monitor.sh`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `UM_WARN` | `80` | порог 🟡-предупреждения, % |
| `UM_CRIT` | `95` | порог 🔴-предупреждения, % |
| `UM_RESET_MIN` | `50` | минимальное использование, при котором сброс окна заслуживает уведомления |
| `UM_CACHE_TTL` | `60` | срок жизни кэша ответа API, сек |
| `UM_LANG` | `ru` | язык сообщений: `ru` или `en` |
| `UM_COMPACT_WARN` | `70` | порог подсказки о `/compact`, % контекста |
| `UM_CONTEXT_WINDOW` | `200000` | размер окна контекста для расчёта процента (перебивается `autoCompactWindow` из `settings.json`) |
| `UM_STATUSLINE_MODEL` | `1` | показывать в statusline сегмент модели |
| `UM_STATUSLINE_CTX` | `1` | показывать `ctx N%` в сегменте модели |
| `UM_SUBAGENT_MODEL` | `1` | показывать модель работающего субагента |
| `UM_SUBAGENT_TTL` | `180` | сколько секунд после последней записи субагент считается работающим |
| `UM_STATUSLINE_ADVISOR` | `1` | показывать модель советника (`/advisor`) |
| `UM_STATUSLINE_RESET` | `1` | время сброса рядом с окном, дошедшим до порога: `5ч 84% ↻00:20`, дальше суток — дата `↻15.10` |
| `UM_FORECAST` | `1` | уведомление ⏳, если при нынешнем темпе лимит кончится до сброса |
| `UM_SPEND_ALERT` | `1` | уведомление 💳 о платных usage credits |
| `UM_STATUSLINE_PACE` | `1` | `▲N` / `▼N` у недельного окна, которое опережает равномерный темп или отстаёт от него на 5 пунктов и больше |
| `UM_STATUSLINE_BG_REFRESH` | `1` | statusline сама обновляет устаревший кэш в фоне (нужно, чтобы видеть расход с других устройств без фонового агента) |
| `UM_STATUSLINE_REFRESH_AFTER` | `120` | возраст кэша в секундах, после которого statusline запускает обновление |

Интервал фоновой проверки — `StartInterval` (секунды, по умолчанию 92) в
`~/Library/LaunchAgents/com.claude.usage-monitor.plist`. Если endpoint ответит
401, 403 или 429, агент сам делает паузу (5 минут и дольше), а не спрашивает
каждые 92 секунды.

## Диагностика

Первым делом — `doctor`. Он проверяет установку по файлам, не обращаясь к
endpoint (безопасно даже во время паузы после 429): токен в Keychain, аккаунт,
возраст данных, паузу, последнюю ошибку, историю, фоновый агент, statusline,
хуки, двойную установку и устаревшую сессию плагина.

```
$ ~/.claude/scripts/usage-monitor.sh doctor
claude-code-limit-alerts vX.Y.Z
· Установка: install.sh, состояние в /Users/you/.claude/scripts
✓ jq: /opt/homebrew/bin/jq
✓ Токен в Keychain: есть, план max
✓ Аккаунт: 1a2b3c4d-5e6f7a8b
✓ Последние данные: 1 мин назад
✓ История: 1240 замеров за 6 д
✓ Фоновый агент: включён, каждые 92 с
✓ Statusline: включена
· Баннеры отсюда не проверить: 'doctor --notify' пришлёт тестовый.
```

`doctor --notify` присылает тестовое уведомление. В плагине то же делает
скилл `limit-alerts:doctor`.

Каждое отправленное уведомление и каждая неудачная попытка получить данные
(протухший токен, 403 для team/org-аккаунтов, устаревший локальный кэш и т.д.)
пишутся в лог с указанием причины:

```bash
cat ~/.claude/scripts/usage-monitor.log       # весь лог
grep "fetch failed" ~/.claude/scripts/usage-monitor.log | tail -30   # только сбои опроса
tail -f ~/.claude/scripts/usage-monitor.log   # смотреть в реальном времени
```

Если строк `fetch failed: ...` подряд много — это не баг: живой эндпойнт
недоступен (см. FAQ ниже), а фолбэк на локальный кэш ждёт, пока не станет
доступен свежий (не старше часа) `cachedUsageUtilization` из `~/.claude.json`.

Проверить состояние launchd-агента:

```bash
launchctl list | grep com.claude.usage-monitor
```

## Удаление

Плагин: сначала `/limit-alerts:uninstall`, затем удалите плагин через
`/plugin`. Порядок важен — отключение плагина само по себе не снимает
statusline и не выгружает launchd-агента, потому что это записи за пределами
плагина.

Классическая установка:

```bash
./uninstall.sh
```

Выгружает launchd-агент, убирает хуки из настроек, возвращает прежний statusline
и удаляет скрипты.

## Экспериментально: mod с командой `/limits`

В `mods/limit-alerts-status/` лежит отдельный плагин на TypeScript-хуках
Claude Code (mod). Он добавляет команду `/limits`: сводка печатается сразу,
**без хода модели и без токенов** — в отличие от скилла `limit-alerts:status`,
который отвечает через модель. Работает и посреди хода.

```
Лимиты Claude Code
⚠ Сессия (5ч): 87% — сброс 15:19 (через 2 ч 50 мин)
⚠ Неделя (все модели): 90% — сброс 15.10 19:59 (через 5 д 7 ч) · по графику 24%
Неделя (Fable): 4%
Источник: последний ответ API этой сессии. Недельный лимит по модели — из кэша монитора (5 мин назад).
```

Для каждого окна берётся более свежая цифра — из последнего ответа API этой
сессии или из `usage-monitor-cache.json` (из `UM_STATE_DIR`, `~/.claude/scripts`
или каталога данных плагина `limit-alerts`), как и в statusline; сводка
говорит, откуда взято каждое окно. Недельный лимит по модели — всегда из кэша. У недельных окон — «по графику», как в `status`; из кэша же — расход недели по продуктам и платные credits. Если монитор сейчас выжидает после ответа 429, сводка это говорит.

Запуск:

```bash
claude --plugin-dir mods/limit-alerts-status
```

Настройки (`lang`, `warn`, `crit`, `state_dir`) появляются в меню
конфигурации. В плагин `limit-alerts` и в marketplace mod не входит: API модов
пока в early access и может меняться между версиями Claude Code.

## FAQ

**Я переключаюсь между несколькими аккаунтами — цифры не перепутаются?**
Нет. Всё привязано к текущему входу (аккаунт + организация из
`~/.claude.json`): у каждого аккаунта своё состояние уведомлений и своя пауза
после ошибок, кэш и statusline показывают только цифры текущего аккаунта.
Переключение не вызывает ложных «♻️ сброшен» и повторных предупреждений.

**Работает ли с Team и Enterprise, а не только с личной подпиской?**
Да, источники данных одни и те же для любого входа через claude.ai. Statusline
берёт 5ч/7д из того, что Claude Code сам передаёт ей из ответов API, — это не
зависит от типа подписки. Монитор спрашивает тот же endpoint, что и `/usage` в
Claude Code; если для вашего аккаунта он отвечает 403 (встречалось у
Team/организаций), монитор один раз обновляет данные через сам Claude Code
(`claude -p /usage`) и делает паузу, а не повторяет запрос каждые 92 секунды.
Окна, которых у вашего плана нет, просто не показываются — без ложных `0%`.

**Уведомления не приходят.**
Проверьте, что уведомления от «Script Editor» разрешены:
Настройки macOS → Уведомления. Скрипт шлёт их через `osascript`.

**Это официальный инструмент Anthropic?**
Нет. Используется недокументированный endpoint, которым пользуется сам Claude Code
для команды `/usage` — формат ответа может измениться. Скрипты в этом случае
тихо перестанут показывать данные (ничего не сломается).

**Токен протухнет?**
Claude Code сам обновляет OAuth-токен при работе; скрипт всегда читает актуальный
из Keychain. Если токен невалиден, проверка тихо пропускается до следующего цикла.
